# Hotel Booking System – Manual Testing Project

## 1. Project Overview

This repository contains manual QA testing documentation for the [Automation in Testing – Hotel Booking Website](https://automationintesting.online/).

The project focuses on understanding the website's functionality, preparing test scenarios and test cases, organizing test data, and documenting identified defects.

The objective is to demonstrate a structured manual testing approach throughout the testing process.

## 2. Application Under Test

**Website:** https://automationintesting.online/

**Testing Type:** Manual Testing

**Project Domain:** Hotel Booking System

**Testing Focus:** Functional Testing, UI Testing, Validation Testing, Negative Testing, and Defect Reporting.

## 3. Repository Contents

This repository contains the following five QA documentation files:

| No. | File Name | Description |
|---|---|---|
| 1 | Project Documentation Hotel Booking System.docx | Provides an overview of the project, application scope, objectives, and testing approach. |
| 2 | Test Scenarios Hotel Booking System.docx | Contains high-level test scenarios covering the application's functionality. |
| 3 | Test Cases Hotel Booking System.xlsx | Contains detailed test cases with steps and expected results. |

## 4. Testing Scope

The testing activities focus on evaluating the website's main functionality and user experience, including:

- Homepage and navigation
- Room availability and booking functionality
- Booking form validation
- Contact form validation
- Input field validation
- Error messages and notifications
- UI layout and alignment
- Links, buttons, and interactive elements
- Negative and boundary-value testing

## 5. Testing Approach

The following approach was followed while preparing the QA documentation:

1. Explore the application and understand its functionality.
2. Identify the main application modules.
3. Prepare high-level test scenarios.
4. Create detailed test cases with expected results.
5. Prepare test data for different testing conditions.
6. Execute testing and observe application behaviour.
7. Document identified defects in the bug report.

- Understanding application requirements and functionality
